# Session Summary 0.1.0

Accepted design for the first public release, not a record of shipped features. See the [glossary](../CONTEXT.md) for the distinction between a session summary and a history outcome.

## What a new user sees

Opening the panel needs no workflow profile, producer script or Git hosting account. Prefer the saved summary of the active session. If there is none, show the last substantive reply of that completed local session under `From session history` when history is enabled. Otherwise, show the shared summary under `Worktree summary` if one exists. If no source applies, say that no summary is available. Never use another session’s reply as the active session’s outcome.

Use English for the panel, accessible labels, settings, CLI messages and documentation. Preserve the author’s language in agent replies, summaries, review drafts and link text. Do not add a language selector in 0.1.0.

## Source Control owns ordinary publication

For a standard GitHub or GitLab project, show a known review link and a `Source Control` menu item that invokes Orca’s built-in action. Do not build a second push or PR/MR creation flow. A user who only reads summaries should never need `gh`, `glab` or a terminal setup.

## Settings and private workflows

Use Orca’s plugin Settings for these preferences:

| Setting | Fresh installation |
| --- | --- |
| Show outcome from local history | On |
| Auto-open the summary for new worktrees | Off |
| Enable profile actions | Off |
| Preferred command action | Copy command |

`Manage profiles` lets a user create and edit a profile in a form or import a local file. Show which projects its rules match before saving. A profile is enabled by its user, never by opening a repository. No match means no profile actions. Two matching profiles must not silently select either one.

When actions are enabled and a single enabled profile matches, show `Next action` below the result. Name the step and destination and show the exact command. `Copy command` keeps the current session in view; `Open terminal` is an alternative for that action. Do not type into an active pane or send Enter. The owner can paste into a shell or use their agent’s shell-command shortcut. A copy earns a `Copied` acknowledgement, never a `Pushed` or `Created` status.

Only show `Edit draft` when a profile prepares a review. The owner can keep, edit or clear the proposed description and edit the title in the panel. If the review URL is already known, show `Open PR` or `Open MR` instead of commands to create another one. A matching profile can supply the way to open the review on another machine.

## Public package and transition

Use `session-summary` as the manifest ID, `0.1.0` as the version and `v0.1.0` as the Git tag. GitHub installs use the publisher’s plugin key. Treat the transition from `local.session-summary` as a separate installation, not a version upgrade. Existing summaries must remain readable without manual moves; the owner enables their private workflow separately.

Ship an MIT license, an English README covering installation from GitHub and the requested permissions, and a neutral example profile. Keep the owner’s real profile, commands, addresses and session data out of public files, fixtures and Git history.

## Release gates

- On **each of macOS, Linux and Windows**, install against a clean Orca profile. Finish a local agent session without a summary producer or workflow profile; verify the panel displays its outcome and attributes it to the right session. Verify settings persist and disabling history stops the panel from using it. A macOS-only profile path, an external `sqlite3` on `PATH`, or Unix permissions are not portable assumptions. An unverified platform blocks this release.
- With two sessions in one worktree, switch between a saved session summary, a history outcome and the shared worktree summary. Verify the labels and contents follow the selection, including the empty state.
- Create a private profile through the UI and import one from a local file. Check a matching project, an unrelated project and a project that matches two profiles. Verify copying a command leaves focus and publication state unchanged. Verify an existing review opens through the chosen route instead of offering creation again.
- On the existing installation, verify that old session and worktree summaries are still readable and the owner’s private workflow still works after they enable the profile. Use private data for this check only, not as public test fixtures.
